# Старт реализации Plan It Today: промпт для Claude Code

> Положи этот файл в `docs/` проекта и дай Claude Code команду: «Прочитай `docs/new-project-kickoff-prompt.md` и начни с шага 0».
> Код пишем только по команде автора. До неё Claude Code работает как разведчик: читает, сверяет, задаёт вопросы.

---

Ты Claude Code в проекте «Plan It Today» (Telegram Mini App). Автор работает соло: спека и обсуждение идеи ведутся в чате Claude (web/Cowork), реализация здесь. Ниже рабочий процесс, накопленный в предыдущем проекте такого же типа (~2 недели от спеки до кликабельного демо). Используй его, но не тащи чужую бизнес-логику.

## Входные данные
- Спека: `docs/spec/plan-it-today.md` (v1.2). Закрытые решения в разделе 15, открытые вопросы и допущения в разделе 16. Контекст проекта: `CLAUDE.md`.
- Дизайн: `docs/design/ui-reference.png` (светлая и тёмная темы). Референс даёт только размеры, цвета и позиции элементов. Где он расходится со спекой, побеждает спека (раздел 12.5). Новые версии референса складываются новым файлом, старые не перезаписываются. Ассеты (иконки, элементы) автор добавит отдельно.
- Платформа: Telegram Mini App. Язык UI: украинский («ШІ», не «ІІ»). Язык общения со мной: русский.
- Хостинг: пока не определён (Docker). Не выбирай сам, добавь вопрос.
- Роль в продукте одна: пользователь. Админ (агрегаты и технические метаданные) появляется только на этапе бэкенда. Экранов админа в демо нет.

## Шаг 0. Разведка (без кода)
1. Прочитай всю спеку и **открой референс** (Read умеет картинки).
2. Составь: список экранов (Інтро и Умови при первом запуске, Планер, Записник, Квест, Майбутнє, Допомога-заглушка, Налаштування, Демо ШІ) → сущности (`Card`, `Step`, подпункты через `parentId`) → бизнес-правила (прогресс с подпунктами, правила дат, состояния кнопок).
3. Выпиши противоречия спеки и референса и всё, чего не хватает, в `CLIENT_QUESTIONS.md` (формат ниже). Если референс показывает фичу, которой нет в спеке, **не делай её молча**, это вопрос.
4. Предложи план батчами (ниже) и жди «ок».

## Шаг 1. Каркас
`CLAUDE.md` уже есть. Обновляй его в конце каждого этапа: что готово (ссылка на последний отчёт), где что лежит, ключевые решения с датами, конвенции. Бюджеты и оценки в репозиторий не попадают.

## Архитектура, которая себя оправдала
**Сначала кликабельное демо на моках, потом бэкенд.** Демо показывается пользователям и тестерам, по нему собирается фидбек, и оно же становится фронтендом MVP.

- Монорепо pnpm: `apps/mini-app`, `apps/api`, `apps/bot`, `packages/shared-types`. Бэкенд (NestJS + Prisma + Postgres в Docker) поднимается **отдельным этапом**: сначала ER-схема и `API_CONTRACT.md`, потом код. Пока бэка нет, фронт без fetch, только моки.
- Mini App: Vite + SCSS + vanilla JS, BEM, без inline-стилей, без новых библиотек и лишних абстракций.
- `src/core/router.js`: реестр экранов + история с параметрами: `navigate(name, params, { reset, replace })`, `back()`. Экран: `{ render(params) → html, mount?, actions? }` в `src/screens/*.js`.
- Клики делегируются из `main.js` через `data-nav` / `data-action` / `data-back` / `data-toast`. Нереализованное: `data-toast="Скоро"`, а не пустая кнопка.
- Одна «мировая» модель моков (`src/data/mock.js`) + состояние и геттеры (`src/data/store.js`). **Демо ШІ-подписки живёт на отдельном наборе моков** и не пишет в реальные карточки пользователя.
- **Даты в моках относительно «сегодня»** (`day: +1`), иначе демо «протухает». Моки-примеры в разделе 10 спеки.
- **Все цифры считаются из данных** (прогресс, счётчики), не хардкодятся.
- **Бизнес-правила чистыми функциями в общем пакете с первого дня** (`packages/shared-types`, при необходимости отдельный `packages/shared`): правила дат (раздел 7), подсчёт прогресса с подпунктами, доступность кнопки «Завершити квест». Фронт импортирует их через alias в `vite.config`, бэкенд как пакет.
- Стили: токены темы в `_base.scss` (светлая + тёмная через CSS-переменные: `--bg-paper`, `--pencil-main`, `--pencil-muted`, `--accent-color`), BEM-партиалы в `styles/blocks/`. Исключение для inline: CSS custom properties под динамические данные.
- В dev выстави `window.demo = { navigate, store, mock }` для быстрых проверок.

## Как работаем
- **Батчи маленькие.** Предлагаемый порядок: 1) каркас + тема + онбординг (Інтро, Умови, флаги `introSeen`/`termsAcceptedVersion`) + нижняя навигация (4 вкладки); 2) Планер + Записник; 3) Квест (чеклист, подпункты, прогресс, «Завершити квест»); 4) Майбутнє + правила дат; 5) Допомога-заглушка + Налаштування; 6) Демо ШІ (60 секунд, автосценарий). После каждого: проверка в браузере и короткий итог.
- **Проверяй сам в браузере**, не «должно работать»: Playwright-кроулер по `data-nav`/`data-action` (ловит ошибки консоли) + сценарные прогоны ключевых флоу (создать карточку → шаги → подпункт → завершить; дата словами; демо ШІ). Ширина 360 px (меньше не поддерживаем), обе темы. Скрипты и скриншоты в scratchpad, не в репо.
- **Не останавливайся на неизвестном:** выбери простое решение, отметь «Допущення» в отчёте и добавь вопрос в `CLIENT_QUESTIONS.md`. Блокируйся только если ошибка дорогая (юридические тексты, деньги, необратимые действия).
- **Не делай git commit / push**, пока я не скажу. Работа идёт в ветке этапа.
- Визуальные проходы под новые макеты делай деликатно: токены и стили компонентов, без редизайна одобренного.
- Код production-ready, комментариев минимум.

## Документы, которые ведём
- `CLIENT_QUESTIONS.md`: вопросы, сквозная нумерация, **одна короткая строка на вопрос**, у каждого «Припущення». Отвеченные переносить в «Закрито (дата)» с кратким решением. Источник начальных вопросов: раздел 16 спеки.
- `reports/YYYY-MM-DD-<этап>.md`: после каждого этапа: что сделано, допущения, новые вопросы, что дальше. Это хендофф для чата Claude, который ведёт спеку.
- `<этап>-prompt.md`: промпты этапов (пишет чат Claude по ответам). Структура: «Контекст: что прочитать» → «Правила» → «Порядок» → секции A, B, C → «Не делай».
- `docs/feedback/<дата>/`: скрины и тексты фидбека тестеров.

## Telegram Mini App
- Стартовый вход: menu button бота и ссылка с `startapp`; поле заметки в фокусе при открытии.
- Auth на бэкенде (позже): `Authorization: tma <initData>` → проверка HMAC от bot token + TTL → upsert пользователя по Telegram ID.
- Тема: стартовое значение из системной (`prefers-color-scheme`), можно сверять с `Telegram.WebApp.colorScheme`; переключатель в «Налаштуваннях».
- Внешние ссылки (сайт поддержки) открываются через `Telegram.WebApp.openLink`.
- В API нет «свернуть»: не рисуй такую кнопку. Есть `BackButton`, `SettingsButton`, `themeParams`, `HapticFeedback`.
- Mini App не работает в фоне; нагадування в MVP нет.
- Тестовый бот в BotFather: Menu Button → URL демо, чтобы тестеры открывали без запущенного бота.

## Грабли окружения
- pnpm запускать через `corepack pnpm`, если в домашней папке есть `package.json`, навязывающий yarn.
- Фоновая вкладка Chrome троттлит таймеры до ~1/мин: проверки с таймерами (демо ШІ на 60 секунд) гонять в headless/синхронно.
- Python 3.9 + кириллица в скриптах: добавляй `# -*- coding: utf-8 -*-`.

## Чего избегать
- Реализовывать фичи «с макета», которых нет в спеке (например, чекбоксы на квестах в «Майбутнем»).
- Хардкодить цифры на экранах.
- Держать правило в двух местах (фронт, сид БД, спека) без единого источника.
- Большие батчи без промежуточного показа.
- Абзацы в вопросах: пользователи отвечают только на короткие.
- Делать реальный ШІ-разбор, оплату или аналитику текста заметок в MVP: это следующий этап.
